## Notes
- **Server vs client**: All search/filter/pagination/sort are **server-side** (`Member::search/status/gender->paginate`); frontend only debounces and resets `page` to 1 on filter change.
- **Member code**: auto `MEM-0001` via `booted creating` + `generateMemberCode()` (next id); unique index prevents dup. Could switch to `MAX(member_code)` if id gaps matter.
- **Validation**: Store requires `first/last`, Update uses `sometimes`; email `unique:members,email` with ignore on update; birthdate `before:today`.
- **Auth**: `apiResource` behind `role:admin` → member `403` as tested; frontend `ProtectedRoute` also gates `/members` to admin.
- **Mobile-first**: `hidden sm:block` table vs `sm:hidden` cards, `grid-cols-1 sm:grid-cols-2` form, `Dialog` `max-h-[90vh] overflow-y-auto` so no overflow on 375px, `min-h-11` buttons.
- **Future**: Add `photo` upload (currently string), bulk import, export CSV/PDF per Reports, and `member_code` editable guard.
