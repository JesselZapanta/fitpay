## Summary
Implemented universal profile update for **both roles**. Backend provides JWT-guarded `GET/PUT|POST /profile` with single-field email lock (no email change), photo stored to `storage/photos` on `users.photo` with old-file cleanup, and secure password rotation. Frontend Profile page is fully mobile-first (single column `grid` → `lg:grid-cols-[320px_1fr]`), Tailwind `w-full min-w-0` + `break-words` to prevent overflow, `min-h-11` touch targets, `cursor-pointer` buttons, `text-sm sm:text-base` scales. `FitPay Admin admin@fitpay.test` block in **both top nav and sidebar** for Admin (and equivalent avatar/name block for Member) now navigates to `/profile`; target page shows email as `disabled` + muted `bg-[var(--surface-0)] cursor-not-allowed` with explanatory copy.

## Notes
- Email is **read-only by design**: no validation for email on update; `UpdateProfileRequest` omits `email` field, frontend disables input. To change email contact admin/support.
- Photo URL resolution handles `blob:`/`http`/`/storage/` via `import.meta.env.VITE_API_URL` fallback to `http://localhost:8000`; requires `php artisan storage:link` on fresh deploy.
- Password change is optional: only sent if `password` filled; backend requires `current_password` and checks with `Hash::check`, returns `422` with `errors.current_password` mapped to UI.
- `POST /profile` exists alongside `PUT` to support `FormData` (`api.js` strips `Content-Type` for FormData so boundary is auto-set); frontend uses `api.post("/profile", fd)`.
- Type-safe guard: `ProtectedRoute` without `roles` allows any authenticated user for `/profile`; role-specific aliases preserve deep-link compatibility (`/member/profile` stays valid for existing nav bookmarks).
- Verification: `php -l` clean for all new controllers/requests; `php artisan route:list` confirms 3 profile routes; `vite build` succeeded (557k js, 77k css, gzip 165k).
- Follow-up: consider public disk quota, avatar cropping UI, rate-limit `/profile` updates, and unified `PATCH /me` alias for consistency.
